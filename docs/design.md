# ReadHorizon 설계 결정 기록

## 1. 목표

텍스트 형식의 작품(소설·시·희곡·수필·고전 문학·논문·교재·기사 등)을 분석해 이해를 돕고,
수능 국어처럼 독자의 문맥·문단·흐름·의미·번역 이해를 지원한다.

## 2. 해석 방식 — "기존 해석 중심 + 보조 생성" 하이브리드

| 선택지 | 결정 |
|---|---|
| ① 외부 검색·학습으로 해석 생성 | 보조로만 사용. 외부 자료는 출처 등급을 붙이고 참고용으로 표시 |
| ② 이미 존재하는 해석을 중심으로 | **뼈대로 채택**. 원문 + 검증된 참고자료(RAG)에 근거한 답을 우선 |

- "러닝"은 모델 파인튜닝이 아니라 **RAG(검색 증강)** 로 시작한다. 출처 인용이 가능하고, 자료를 넣고 빼는 것이 즉시 반영되며, 저작권 관리가 쉽다.
- 파인튜닝은 벤치마크와 피드백 데이터가 쌓인 뒤 해설 형식을 맞추는 용도로만 검토한다.
- 해석은 두 층으로 나눈다. 사실 층(줄거리·화자·시점·표현법·어휘)은 근거가 필수이고, 해석 층(주제·상징·의도)은 복수 관점을 허용한다.

## 3. 작품 입력

| 단계 | 입력 | 상태 |
|---|---|---|
| 1차 | TXT · MD · PDF · DOCX · HWPX 업로드, 원문 붙여넣기 | 구현 |
| 1차 | 책 소개 붙여넣기(선택) | 구현. 소개만 있으면 읽기 가이드 전용 |
| 2차 | 이미지·스캔 PDF(OCR), HWP 5.0 바이너리 | 예정. 옛한글 인식 검증 필요 |
| 3차 | 외부 연동(Drive·Notion 등) | 예정. 최소 권한, 3자 제공 최소화 |

모든 입력은 공통 문서 구조로 정규화한다: **섹션 > 문단**(운문은 **연 > 행**). 인용 위치가 문단·행 번호로 돌아온다.

## 4. 서점 책 소개 정책

- 서점 페이지(교보문고·알라딘 등)는 **크롤링하지 않는다**. 약관의 자동 수집 금지, 데이터베이스제작자 권리(저작권법 제93조), 부정경쟁방지법이 걸릴 수 있고, 소개글 저작권은 출판사에 있다.
- 알라딘 Open API는 2026-10-30에 종료된다(신규 키 발급은 2026-09-04 종료). 설계에서 제외한다.
- 서지정보는 **국립중앙도서관 ISBN 서지정보 API**(공공)를 쓴다. 외부로 보내는 값은 제목 또는 ISBN뿐이다.
- 책 소개는 **사용자가 직접 붙여넣은 경우에만** 쓴다.
  - C등급 `사용자 제공 소개`로 따로 표시하고 해석 근거로 쓰지 않는다(근거율 계산에서도 제외).
  - 원문이 없으면 "제한 분석" 모드로 전환해 읽기 가이드만 제공한다.
  - 입력은 해당 사용자의 자료실에만 저장한다. 공용 DB에 모으면 사실상 우회 수집이므로 하지 않는다.
  - 서점 페이지를 자동으로 긁는 확장 기능은 만들지 않는다.
  - 소개글 입력은 5,000자로 제한한다(원문 전체를 소개란에 넣는 것을 막기 위함).

## 5. 신뢰도 검증 체계

| 계층 | 구현 |
|---|---|
| ① 출처 등급 | 원문(1차) / A 공식·학술 / B 사전·평론 / C 참고. 공용 참고자료는 가져올 때 등급·출처·라이선스를 필수로 받는다 |
| ② 근거 연결 | Claude Citations. 원문은 문단=블록인 custom content 문서로 보내 `content_block_location`(0부터 시작, 끝 번호 미포함)으로 문단 번호를 돌려받는다 |
| ③ 자동 검사 | 인용문이 해당 원문 구간에 실제로 있는지 공백을 무시하고 대조한다. 실패하면 ⚠ 표시 |
| ④ 근거율 | 분석 본문을 문장(목록 항목) 단위로 나눠, 원문·A·B 인용이 붙은 문장의 글자 비율을 계산한다. 60% 이상이면 "원문 근거 충분", 30% 이상이면 "일부 근거", 그 아래는 "AI 해석 비중 높음" |
| ⑤ 정량 평가 | 선다형 벤치마크(`readhorizon eval`)로 정답률과 평균 근거율을 측정한다. 실제 기출은 이용 조건 확인 후 준비 |
| ⑥ 사람 검수 | 운영 단계에서 표본 전문가 검토, 사용자 신고 (예정) |

Citations와 structured outputs(`output_config.format`)는 함께 쓸 수 없으므로, 분석 결과는 마크다운 텍스트와 인용 블록으로 받는다.

## 6. 카테고리

| 카테고리 | 장르 | 비고 |
|---|---|---|
| 문학 | 소설 · 시 · 희곡 · 수필 | 장르별 분석 항목 |
| 학습·연구 | 수능 독서 · 수능 문학 · 논문 · 교재 | 수능은 출제 포인트, 고전은 현대어 뜻 포함 |
| 사용자 지정 | 기사 · 강의 자료 · 일반 | 장르가 아니라 "내 자료실" 성격. 사용자별로 분리하고 공용 모델·DB에 섞지 않음 |

MVP는 **수능 국어(문학·독서)** 를 중심 사용 사례로 삼는다. 문학 영역과 독서(비문학) 영역이 카테고리 1·2의 핵심을 함께 다루고, 공식 정답이 있어 정확도를 숫자로 확인할 수 있다.

## 7. 개인정보·보안

- 수집하지 않음: 이름, 이메일, 전화번호, 계정, 위치.
- 자료실 ID: 브라우저가 만든 무작위 UUID. 모든 조회·분석은 자료실 ID로 분리한다.
- 자동 마스킹(저장·전송 전): 주민·외국인등록번호, 카드번호, 휴대전화·유선 전화번호, 이메일. ISBN·연도·날짜는 가리지 않는다.
- 마스킹 기록: 항목과 개수만 남기고 값은 남기지 않는다. 화면에서 최근 30일 항목별 개수를 고지한다.
- 보관 기간: 마지막 이용 후 180일(설정 가능)이 지나면 작품·분석·질문을 삭제한다(서버 시작 시, `readhorizon purge`).
- 외부 처리: Claude API(마스킹된 원문·소개·질문), 국립중앙도서관 API(검색어·ISBN). 화면에서 고지한다.
- 웹 보안: CSP(`script-src 'self'`, 인라인 스크립트·스타일 없음), 모든 사용자 텍스트는 escape 후 렌더링, 출처 URL은 http(s)만 허용.
- 업로드 방어: 요청 크기를 Content-Length로 먼저 거르고(길이 없는 chunked 요청 거부), DOCX·HWPX 압축 해제 크기를 제한하며, HWPX XML은 defusedxml로 DTD·엔티티를 거부한다(엔티티 폭탄·XXE 차단). 손상 PDF의 예외는 모두 사용자 메시지로 바꾼다.
- 비용 보호: 분석·질문(LLM 호출)은 접속 IP별 분당 횟수와 프로세스 전체 일일 횟수를 제한한다(저장된 결과 조회는 제외). IP는 메모리에서 1분만 쓰고 저장하지 않으며, 접속 로그는 기본으로 남기지 않는다.
- 입력 정규화: 모든 텍스트를 NFC로 맞추고 제어 문자·보이지 않는 문자를 지운다. macOS의 NFD 한글 파일명·본문도 검색·인용 대조가 어긋나지 않는다.
- 보관 기간 정리는 서버 시작 시와 운영 중 1시간마다 실행한다.
- 의존성 하한은 pip-audit 기준 알려진 취약점이 없는 버전으로 맞춘다.
- 프롬프트 인젝션: 문서 내용은 데이터로만 다루라고 시스템 프롬프트에 명시하고, 원문은 document 블록으로 분리해 보낸다.

## 8. 비용

- 시스템 프롬프트는 고정하고, 작품 원문 문서에 `cache_control`을 걸어 같은 작품의 반복 분석·질문에서 prompt caching을 쓴다.
- 분석 결과는 저장해 두고 "다시 분석"을 누를 때만 새로 호출한다.
- 긴 작품은 글자 수 한도 안에서 관련 문단(질문 시)이나 고르게 뽑은 문단(분석 시)만 보낸다.

## 9. 알려진 한계

- 자료실 ID는 인증이 아니다. 공개 운영 전에 계정 인증이 필요하다.
- 호출 제한은 프로세스 메모리에서 센다. 서버를 여러 대로 늘리면 프록시·게이트웨이 제한을 함께 둔다.
- 분석은 동기 요청이라 1~2분 걸릴 수 있다. 리버스 프록시의 응답 대기 시간을 늘려야 하며, 작업 큐 + 진행 상태 조회 방식은 다음 단계에서 검토한다.
- 긴 작품의 전체 분석은 발췌 기반이다. 장 단위 요약을 이어 붙이는 방식(map-reduce)은 다음 단계에서 다룬다.
- 참고자료 검색은 한글 2-gram BM25다. 자료가 많아지면 형태소 분석기와 벡터 검색(pgvector)으로 확장한다.
- 국립중앙도서관 API 응답 필드 이름은 기관 문서를 기준으로 방어적으로 읽는다. 실제 키로 첫 호출할 때 확인이 필요하다.
