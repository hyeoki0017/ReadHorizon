실험 1 · 치환 암호와 통계

카이사르와 비즈네르, 그리고 빈도 분석

글자를 바꿔도 언어의 통계는 남습니다. 암호문 글자 빈도를 영어의 기대 빈도와 비교해, 키를 모른 채로 평문을 되찾아 보세요.

핵심 개념

카이사르 암호는 모든 글자를 같은 거리 k만큼 민다(키 공간 26). 비즈네르 암호는 키 글자마다 다른 거리를 써서 단일 빈도 분포를 평평하게 만든다.

카이사르 C = (P + k) mod 26 비즈네르 Cᵢ = (Pᵢ + K_(i mod m)) mod 26 카이제곱 χ² = Σ (관측ᵢ − 기대ᵢ)² / 기대ᵢ ← 작을수록 영어에 가깝다 일치지수 IC = Σ nᵢ(nᵢ−1) / (N(N−1)) ← 영어 ≈ 0.066, 무작위 ≈ 0.038

비즈네르 해독은 두 단계다. ① 키 길이 m 후보마다 m개 열로 나눠 평균 IC를 구하면, 올바른 m에서 IC가 영어 수준으로 뛴다. ② 각 열은 카이사르 암호이므로 χ²가 가장 작은 이동량이 그 열의 키 글자다.

실험 2 · 공개키 암호의 연산 도구

확장 유클리드 호제법과 빠른 거듭제곱

RSA·디피–헬만·타원곡선은 모두 두 연산 위에 서 있습니다. 모듈러 역원을 구하는 확장 유클리드, 그리고 지수의 비트 수만큼만 곱하는 제곱-곱셈법입니다.

핵심 개념
베주 항등식 a·s + m·t = gcd(a, m) gcd = 1 이면 a⁻¹ ≡ s (mod m) 제곱-곱셈 지수 e를 2진수로 읽으며 비트마다 acc ← acc², 비트가 1이면 acc ← acc·b 비용 곱셈 약 2·log₂e 회 (단순 반복은 e−1 회)

모든 값은 임의 정밀도 정수(BigInt)로 계산하므로 수백 자리 수도 넣을 수 있습니다.

실험 3 · 인수분해의 어려움

RSA 키 생성부터 공격까지

작은 소수로 키를 만들고, 암호화·복호화·CRT 가속을 확인한 뒤, 같은 키를 직접 인수분해해 깨 봅니다. 비트 수를 늘리며 공격 시간이 어떻게 변하는지 관찰하세요.

핵심 개념
n = p·q, φ(n) = (p−1)(q−1), gcd(e, φ) = 1, d ≡ e⁻¹ (mod φ) 암호화 c = mᵉ mod n 복호화 m = cᵈ mod n CRT m_p = c^(d mod p−1) mod p, m_q = c^(d mod q−1) mod q m = m_q + q·((m_p − m_q)·q⁻¹ mod p) ← 약 4배 빠르다

이 실험의 RSA는 패딩이 없는 '교과서 RSA'입니다. 결정적이고 곱셈 준동형이라 그대로 쓰면 안전하지 않습니다. 실제로는 OAEP(암호화)·PSS(서명) 패딩과 2048비트 이상의 n을 씁니다.

키 생성

정수 하나 암호화 CRT 복호 비교

곱셈 준동형 교과서 RSA의 약점

공격자는 d 없이 암호문만 곱해 m₁·m₂의 암호문을 만들 수 있습니다. 패딩이 이 구조를 깨뜨립니다.

문장 암호화 UTF-8 바이트마다 따로 암호화

같은 바이트는 늘 같은 암호문이 됩니다(A, T, 공백을 찾아보세요). 결정적 암호화는 결국 거대한 치환 암호이고, 실험 1의 빈도 분석이 그대로 통합니다.

공격: n을 인수분해해 d 복원하기

버튼을 눌러 현재 n을 인수분해해 보세요.

시행 나눗셈은 약 √n ≈ 2^(비트/2)번, 폴라드 ρ는 약 n^(1/4)번 걸립니다. 2048비트 n에는 둘 다, 그리고 가장 빠른 알려진 방법(일반 수체 체)도 현실적인 시간 안에 닿지 못합니다.

생각해 볼 문제

  1. p = q로 두면 어떤 일이 생기나요? φ(n)을 다시 계산해 보고 왜 p ≠ q여야 하는지 설명하세요.
  2. e = 3이고 m³ < n이면, 공격자는 d 없이 m을 어떻게 구할 수 있나요?
  3. 소수 크기를 16 → 24 → 32 → 40비트로 늘리며 폴라드 ρ 반복 횟수를 기록하고, n^(1/4) 예측과 비교해 보세요.
실험 4 · 이산로그 문제

디피–헬만 키 교환과 중간자 공격

공개 채널에서 비밀 없이 같은 키를 만드는 과정입니다. 도청자 이브의 입장에서 이산로그를 풀어 보고, 인증이 없을 때 끼어드는 중간자 공격도 켜 보세요.

핵심 개념
공개 소수 p, 생성원 g 앨리스 a 비밀, A = gᵃ mod p 전송 밥 b 비밀, B = gᵇ mod p 전송 공유 키 K = Bᵃ = Aᵇ = gᵃᵇ mod p 이산로그 A, g, p로부터 a 찾기 — 전수 조사 O(p), 아기걸음-거인걸음 O(√p)

안전소수 p = 2q + 1 (q도 소수)을 쓰면 생성원 판정이 쉽고, 작은 부분군 공격을 피할 수 있습니다. 실제로는 2048비트 이상 p 또는 타원곡선(X25519)을 씁니다.

공개 매개변수

이브의 공격: A에서 a 찾기

p를 키워 가며 두 방법의 연산 횟수를 비교해 보세요. 전수 조사는 300만 번에서 멈춥니다.

생각해 볼 문제

  1. 중간자 공격을 켜면 앨리스와 밥은 각자 '키 교환 성공'이라고 믿습니다. 무엇을 추가하면(서명, 인증서 등) 이 공격을 막을 수 있나요?
  2. g의 위수가 작으면(예: g = p − 1) 공유 키가 몇 가지 값만 가질 수 있습니다. 직접 넣어 확인해 보세요.
  3. 아기걸음-거인걸음은 시간을 √p로 줄이는 대신 무엇을 대가로 치르나요?
실험 5 · 치환-순열 네트워크

AES-128 라운드를 한 단계씩

16바이트 상태 행렬이 10라운드 동안 어떻게 섞이는지 봅니다. 이전 단계와 달라진 바이트가 강조됩니다. 아래에서 평문 1비트를 뒤집어 눈사태 효과도 측정해 보세요.

핵심 개념
AddRoundKey(0) 라운드 1–9 SubBytes → ShiftRows → MixColumns → AddRoundKey 라운드 10 SubBytes → ShiftRows → AddRoundKey (MixColumns 없음) SubBytes GF(2⁸) 역원 + 아핀 변환 → 비선형성(혼돈, confusion) ShiftRows r행을 왼쪽으로 r칸 → 열 사이 확산 MixColumns GF(2⁸) 위 4×4 행렬 곱 → 열 안 확산(diffusion)

상태 행렬은 열 우선으로 채웁니다: 입력 바이트 i는 (행 i mod 4, 열 ⌊i/4⌋). 이 구현은 S-box를 표로 적지 않고 GF(2⁸) 역원과 아핀 변환으로 직접 계산합니다.

입력 16진수 32자

라운드 1 슬라이더로 0–10 라운드 이동

눈사태 효과 128비트 중 달라진 비트 수, 라운드별

012345678910

점선은 무작위 기대값 64비트입니다. 두 라운드면 대략 절반이 바뀝니다(완전 확산).

  3. 키의 비트 하나를 바꿨을 때도 눈사태 효과가 나타나는지 예측하고, 키를 고쳐 확인해 보세요.
실험 6 · 블록 암호를 긴 데이터에

ECB가 이미지를 숨기지 못하는 이유

같은 그림을 AES-128로 ECB·CBC·CTR 모드에서 암호화합니다. 회색조 픽셀 하나가 1바이트이므로, 가로 16픽셀이 한 블록입니다.

핵심 개념
ECB Cᵢ = E_K(Pᵢ) 같은 블록 → 같은 암호문 CBC Cᵢ = E_K(Pᵢ ⊕ Cᵢ₋₁), C₀ = IV IV는 예측 불가능해야 함 CTR Cᵢ = Pᵢ ⊕ E_K(nonce ‖ i) nonce 재사용 금지, 병렬 처리 가능

실무에서는 기밀성과 무결성을 함께 주는 인증 암호(AES-GCM, ChaCha20-Poly1305)를 씁니다.

생각해 볼 문제

  1. ECB 그림에서 윤곽이 보이는 영역과 보이지 않는 영역은 각각 어떤 픽셀 패턴인가요? 사진처럼 잡음이 많은 이미지를 넣으면 어떻게 되나요?
  2. CBC 암호문 한 블록에서 비트 하나가 깨지면 복호 시 몇 블록이 영향을 받나요? CTR은요?
  3. nonce 재사용 실험에서 C₁ ⊕ C₂만으로 두 평문의 윤곽이 보입니다. 같은 일이 WEP·스트림 암호 사고에서 어떻게 일어났는지 조사해 보세요.
실험 7 · 충돌 저항성

SHA-256 눈사태와 생일 공격

글자 하나만 바꿔도 다이제스트 비트의 절반쯤이 바뀝니다. 그리고 출력을 n비트로 자르면 약 2n/2번 만에 충돌이 나는 생일 역설을 직접 재현합니다.

핵심 개념
역상 저항성 h가 주어졌을 때 H(x) = h 찾기 ≈ 2ⁿ 제2역상 저항성 x가 주어졌을 때 H(x') = H(x) 찾기 ≈ 2ⁿ 충돌 저항성 H(x) = H(x')인 아무 쌍 찾기 ≈ √(π/2)·2^(n/2) ≈ 1.25·2^(n/2)

SHA-256은 메르클–담고르 구조로 512비트 블록을 64라운드 압축 함수에 넣습니다. 이 페이지의 SHA-256은 직접 구현했고, 아래 'abc' 시험 벡터로 검증됩니다.
