# 보안·개인정보 점검표 (exam_booker)

기준: 개인정보 보호법(최소수집·안전성 확보조치·처리방침), 개인정보의 안전성 확보조치 기준(고시),
OWASP 비밀번호 저장 권고. 점검일 2026-10-11, 대상: **1인용 로컬 실행 버전**(본인 PC에서 본인 계정만 사용).

> ✅ 충족 · ⚠️ 사용자 조치 필요 · ❌ 미충족(이 버전 범위 밖)

## 1. 개인정보 최소 수집·이용

| 항목 | 상태 | 내용 |
|---|---|---|
| 수집 항목 최소화 | ✅ | 처리하는 것은 **접수 사이트 아이디·비밀번호뿐**. 이름·주민번호·연락처·사진은 다루지 않음(접수 화면에 이미 저장된 정보를 사이트가 쓰는 것) |
| 목적 외 이용·제3자 제공 | ✅ | 외부 전송 없음. 통신은 ① 사용자가 설정한 접수 사이트 ② 그 사이트에 서버 시각 확인용 HEAD 요청뿐. 분석·통계·광고 전송 없음 |
| 설정 파일 평문 금지 | ✅ | `login`에 `password`·`id`·`pw` 등 키가 있으면 실행 거부 |
| 화면·로그 노출 | ✅ | 아이디는 `sa****01` 형태로 가림, 비밀번호는 출력 경로 없음. `Credential` 객체를 print해도 가려짐 |
| 화면 구조 확인(inspect) | ✅ | 입력칸의 이름·종류만 출력하고 **입력값은 읽지 않음** |
| 보유 기간·파기 | ⚠️ | 보관함·로그인 쿠키는 사용자가 지울 때까지 남음 → 접수 후 `python -m exam_booker cleanup --vault-too` 권장 |

## 2. 안전성 확보조치 (암호화·접근통제)

| 항목 | 상태 | 내용 |
|---|---|---|
| 저장 시 암호화 | ✅ | AES-256-GCM(인증 암호화), 항목마다 무작위 12바이트 nonce |
| 키 유도 | ✅ | 마스터 비밀번호 → scrypt(N=2^17, r=8, p=1, 16바이트 무작위 salt) — OWASP 권장값 |
| 위변조·바꿔치기 검출 | ✅ | GCM 태그 + 사이트 이름을 AAD로 묶음 → 다른 항목에 옮겨 붙이면 복호화 실패(테스트 포함) |
| 마스터 비밀번호 | ✅ | 저장하지 않음, 8자 이상 강제, 입력은 getpass(화면 미표시), 환경변수 입력 경로 없음 |
| 메모리 내 평문 | ⚠️ | 키는 bytearray로 보관 후 `lock()`에서 0으로 덮어씀. 아이디·비밀번호 평문은 **로그인 직전에만 복호화**하고 바로 참조를 끊지만, Python 문자열 특성상 메모리 완전 소거는 보장 못 함 |
| 파일 권한 | ✅/⚠️ | 리눅스·맥: 보관함 0600(본인만). **윈도우는 권한 제한 미적용** → 본인 계정 폴더에 두기 |
| 브라우저 비밀번호 저장 | ✅ | 크롬 비밀번호 저장·자동완성 기능을 꺼서 보관함 밖에 평문이 남지 않게 함 |
| 디버그 로그 유출 | ✅ | `DEBUG=pw:api`·`PWDEBUG` 상태에서는 입력값이 로그에 찍힐 수 있어 자동 로그인 거부 |
| 버전관리 유출 | ✅ | `credentials.enc`, `browser_profile/`, `config.yaml`은 `.gitignore`로 커밋 차단 |
| 로그인 쿠키 | ⚠️ | `browser_profile/`에 세션 쿠키가 평문 저장(크롬 기본 동작). 공용 PC 사용 금지, 사용 후 `cleanup` |
| 계정 잠금 방지 | ✅ | 자동 로그인은 1회만 시도, 실패 시 재시도 없이 수동 전환 |

## 3. 대상 사이트 보호장치 존중

| 항목 | 상태 | 내용 |
|---|---|---|
| 보안문자·대기열(넷퍼넬)·추가 인증 | ✅ | 우회하지 않음. 감지되면 멈추고 사람이 처리할 때까지 대기 |
| 요청 빈도 | ✅ | 새로고침 1초 미만 설정 불가 |
| 이용약관 | ⚠️ | 매크로 사용을 제한하는 사이트가 있음. 사용자가 각 사이트 약관 확인 필요 |
| 최종 결제 | ✅ | 기본은 사람이 직접 확정. 결제 정보는 프로그램이 다루지 않음 |

## 4. 처리방침(개인정보 처리방침) 관련

1인용 로컬 버전은 **배포자가 이용자의 개인정보를 받지 않으므로** 배포자가 개인정보처리자가 되지 않습니다.
그래도 배포 시 아래 고지문(README 수록)을 함께 제공하는 것을 권장합니다.

- 처리 항목: 접수 사이트 아이디·비밀번호(이용자 PC에만 암호화 저장)
- 목적: 이용자 본인 계정의 자동 로그인 / 보관: 이용자가 삭제할 때까지 / 제3자 제공·위탁: 없음
- 파기: `cleanup --vault-too` 또는 파일 삭제 / 문의처: 배포자 연락처

## 5. 남은 위험·한계

- 실제 Q-Net·KCA·KISA 화면에서는 검증하지 못함(개발 환경에서 해당 사이트 접속 차단). 프리셋 선택자는 출발점일 뿐.
- 악성코드에 감염된 PC에서는 키 입력·메모리 탈취를 막을 수 없음(로컬 보관 방식의 공통 한계).
- 마스터 비밀번호를 잊으면 복구 불가(설계상 의도). `vault add`로 다시 저장.

## 6. 수익화(회당 1,000~3,000원 자동 접수) 시 추가 점검 — **현재 버전으로는 불충족**

유료로 **타인의 계정으로 대신 접수**하는 순간 성격이 바뀝니다. 아래는 결함 사유가 될 수 있는 항목입니다.
법률 판단은 변호사 검토가 필요합니다.

| 위험 | 수준 | 내용 |
|---|---|---|
| 개인정보처리자 의무 발생 | 높음 | 고객 아이디·비밀번호를 서버에서 받으면 개인정보 보호법상 처리방침 공개, 안전성 확보조치(내부관리계획·접근통제·접속기록 보관·암호화), 유출 시 통지·신고 의무가 생김. Q-Net 계정에는 실명·주민번호 기반 본인정보·사진이 연결돼 있어 **유출 시 피해가 큼** |
| 타인 계정 대리 로그인 | 높음 | 사이트 약관은 보통 본인 외 계정 사용을 금지. 계정 소유자가 동의했더라도 사이트가 허락하지 않은 접속은 정보통신망법 위반 소지 검토 필요 |
| 매크로 이용 영업 | 높음 | 공정한 선착순 접수를 돈으로 앞지르게 하는 서비스는 기관의 차단·접수 취소 대상이 될 수 있고, 형법상 업무방해 해당 여부 다툼 소지. 매크로 부정 이용을 처벌하는 입법이 공연·스포츠 분야로 확대되는 추세 |
| 고객 분쟁 | 중간 | 접수 실패·취소·계정 정지 시 환불·손해배상 책임. 통신판매업 신고·사업자등록·결제대행(PG) 계약 필요 |

**권장 방향** (위험 낮은 순)
1. **알림 서비스**: 접수 시작·취소 자리 발생을 알려 주기만 하고 접수는 본인이 직접 → 계정 정보를 받지 않음
2. **1인용 로컬 프로그램 배포**(현재 구조): 계정 정보가 이용자 PC를 벗어나지 않음. 다만 약관상 매크로 금지 사이트는 이용자 책임 고지 필요
3. 서버에서 고객 계정으로 대리 접수 — **권장하지 않음**
